# Boss 直聘自动投递 Agent — 开发阶段与子任务拆分

本目录将 `workspace/ZhipinPlan.md` 的完整实施方案拆分为可独立交给子 Agent 执行的开发任务。

## 使用方式

1. **按顺序推进阶段**：每个阶段内部的任务尽量并行，但需满足 `depends_on` 中列出的依赖。
2. **子 Agent 执行**：对每个任务，复制对应文件里的「子 Agent Prompt」发给 `Agent` 工具执行。
3. **验收标准**：每个任务都包含明确的交付物与验收标准，完成后在 [tasks.json](./tasks.json) 或本文件中打勾。
4. **前置总上下文**：所有子 Agent 都应先阅读 `workspace/ZhipinPlan.md`。

## 阶段总览

| 阶段 | 名称 | 周期（参考） | 核心交付物 | 依赖 |
|------|------|-------------|-----------|------|
| M1 | 项目脚手架与抽象接口 | 2-3 天 | package.json、tsconfig、Vitest、接口定义、配置/env | - |
| M2 | 浏览器与会话管理 | 2-3 天 | CDP 连接、登录态检查、SessionManager、验证码检测、QR 兜底 | M1 |
| M3 | 职位数据获取与解析 | 5-7 天 | 多层数据获取、字段规范化、搜索翻页、详情双轨、securityId 解析、错误分类重试 | M1、M2 |
| M4 | LLM 筛选模块 | 3-5 天 | LLM 客户端、Prompt、Zod 输出、缓存、阈值 | M1 |
| M5 | 投递流程与并发流水线 | 5-7 天 | 打招呼/投递、Pipeline worker、Orchestrator、限流、Dry-run | M2、M3、M4 |
| M6 | 稳定性、报告与测试 | 4-5 天 | SQLite 存储、WAL/写入队列、报告导出、内存管理、CLI、测试、文档 | M1-M5 |
| M7 | 集成验收与文档 | 2 天 | E2E 验证、README、免责声明、运行手册 | M6 |

## 任务清单索引

详见 [tasks.json](./tasks.json)。每个 JSON 条目包含：

- `id`：任务唯一编号（如 `M1-T1`）
- `phase`：所属阶段
- `title`：任务名称
- `files_to_create` / `files_to_modify`：需要创建或修改的文件
- `depends_on`：必须先完成的任务
- `acceptance`：验收标准
- `prompt`：可直接复制给子 Agent 的完整提示词

## 执行建议

1. **先跑 M1**：没有接口定义和项目结构，后续阶段无法并行。
2. **M2 与 M3 可部分并行**：M3 中的纯解析模块（URL、规范化、参数映射）不依赖浏览器，可在 M1 完成后立即开始；依赖真实浏览器/CDP 的部分等 M2 完成。
3. **M4 可与 M2 并行**：LLM 客户端与 Prompt 只依赖 M1 的接口定义。
4. **M5 必须等 M2/M3/M4**：投递与流水线依赖浏览器、职位数据、LLM 筛选。
5. **M6 穿插进行**：存储、报告、测试可在对应功能实现后逐步补齐，不必全部堆到最后。

## 注意事项

- 所有子 Agent 应遵守现有代码风格、命名规范，并为新增模块编写测试。
- 高风险功能（登录、验证码、请求头/Cookie、反检测）必须先在 `Dry-run` 模式下验证，再开启真实投递。
- 账号安全优先：默认启用 Dry-run、低频率、有头模式、自动截图。
