# 如何通过子 Agent 执行任务

本目录已将 `workspace/ZhipinPlan.md` 拆分为 7 个阶段、40 个可独立执行的子任务。

## 任务索引

- 阶段概览：见 `README.md`
- 每个阶段的任务表与依赖：见 `phase-M*.md`
- 所有任务的完整信息（ID、依赖、交付物、验收标准、可直接复制的子 Agent Prompt）：见 `tasks.json`

## 推荐的执行顺序

1. **M1** 必须全部完成后，再启动需要接口/配置的后续阶段。
2. **M2** 与 **M3** 可部分并行：M3 中的纯数据解析任务（URL、规范化、参数映射）可在 M1 完成后启动；依赖浏览器/CDP 的任务等 M2 完成。
3. **M4** 可与 **M2/M3** 并行，只要 M1 完成。
4. **M5** 必须等 M2、M3、M4 完成。
5. **M6** 穿插进行，但主 CLI 与集成测试需要 M5 完成。
6. **M7** 在所有功能与测试完成后进行。

## 使用 `Agent` 工具执行单个任务

### 1. 查看任务详情

打开 `tasks.json`，找到目标任务，例如 `M1-T2`。

### 2. 复制 Prompt

复制该任务对象中的 `prompt` 字段内容。

### 3. 调用 Agent

在 Claude Code 中使用 `Agent` 工具，例如：

```
Agent(
  description: "M1-T2 定义核心接口",
  prompt: "<复制的 prompt 内容>"
)
```

> 如果任务会修改文件且需要隔离，可加上 `isolation: "worktree"`。

### 4. 验收

子 Agent 完成后，对照该任务的 `acceptance` 列表逐项检查。

## 批量推进一条阶段

如果想让子 Agent 一次完成某阶段内的多个并行任务，可以：

1. 查看该阶段的 `phase-M*.md` 中的任务表。
2. 选择依赖已经满足的任务。
3. 分别调用多个 Agent（它们可以并行运行）。

## 任务依赖查询

`tasks.json` 中每个任务都有 `depends_on` 字段。开始任务前，确保其依赖任务已验收完成。

## 注意事项

- 所有子 Agent 都应先阅读 `workspace/ZhipinPlan.md` 作为全局上下文。
- 子 Agent 应遵守现有代码风格，并为新增模块编写测试。
- 高风险任务（登录、验证码、反检测、真实投递）必须在 **Dry-run** 模式下验证后再开启真实行为。
- 建议在执行 M2/M3 涉及真实浏览器/CDP 的任务时，先在本地确认 Chrome 已安装并可用。
